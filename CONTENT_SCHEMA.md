# Content schema

Primary content: content/research.json. Browser bundle: content/content.js, generated by scripts/build-content.cjs. Original extraction: content/source-extract.json. No interface logic is embedded in scientific content.

IDs are stable and unique **within their collection**; a glossary term and a lesson may intentionally share an id, and the route/kind scopes it.

| Collection | Required learning fields |
|---|---|
| topics | id, title, group, summary, why, detail, evidence, misconception, example, terms[], related[], source, slides[], poster, steps[], support |
| terms | id, term, full, plain, why, mechanism, remember, origin, source, related[], topic, support |
| flashcards | id, topic, front, back, source |
| questions | id, topic, type, difficulty, objective, prompt, answer, explanation, source, support; MCQ additionally options[], correct index |
| comparisons | id, title, headers[], rows[][], source |
| figures | id, title, files[], meaning, caution, source, topic |
| slides | id, number, title, image, message, guide, topic, source, question, answer, questionKind |
| relationships | [from-topic, to-topic, meaning, support-classification] |
| discrepancies | title, detail, source |

Support classes distinguish faithful paraphrases, explanatory interpretations, inferred questions and unresolved source issues. Neither an analogy nor an unanswered question is a new scientific finding. Glossary definitions are educational explanations in source context, not falsely quoted definitions. Historical naming is left unspecified when not supplied.

## Persistent state version 1

`{version, theme, sidebar, read[], bookmarks[], notes{}, ratings{}, answers{}, recent[], rehearsal{}, lastTopic}`.

- notes maps topic/draft ids to strings.
- ratings maps card ids to {grade, level, due, last}; due/last use epoch milliseconds.
- answers maps question ids to {response, correct, at, selfAssessed?}.
- read/recent/bookmarks contain topic ids; rehearsal maps checklist indices to booleans.
- theme is light/dark/colour; sidebar is a desktop-collapse boolean.

core.js validates imported state and scientific links. Maximum backup upload size is 10 MB. Notes and responses are length-limited by import validation and escaped on output. No submitted text is evaluated as HTML or code. Unknown state versions are rejected. Unreadable on-device state is preserved for raw recovery export; an intentional valid import replaces it.

Schema checks validate structure/references, not scientific truth. Scientific content still requires comparison against supplied documents. A draft JSON Schema is also supplied in content/schema.json for tooling; the executable checks are in core.js and scripts/verify_project.py.

## Objective and linking additions in 1.1

objectives[] contains id, number, group/class, title, lessons[], source and support. Every topic belongs to exactly one objective. Glossary terms have aliases[] for whole-word, longest-phrase inline linking. Existing ids and localStorage version remain unchanged.

## Structured teaching content (2.0)

`content/learning.json` holds 145 activities. `content/learning.schema.json` documents the shape and `StudyCore.validateLearning()` enforces coverage, objective references, worked reasoning, distinct prompts, answer keys, feedback, rubrics and no placeholder content during the build.

Each activity has `id`, `title`, `topic`, `objective`, `outcome`, `explanation`, `scenarioLabel`, `worked`, `practice`, `retry`, `mastery`, `commonConfusion`, `source` and optional authoritative `backgroundSources`. A worked demonstration contains a scenario, information, reasoning steps, answer, why and a transferable principle. Questions support `mcq`, `numeric` and `short`. Numeric tasks specify an expected value, absolute tolerance and unit convention; open tasks require a rubric. Submission or explicit reveal controls feedback visibility.

Content owners reference activities through `learning` IDs. All 105 terms, 15 lessons, 7 figures, 10 oral slides and 5 comparisons are covered, together with 2 tables and the methodology schematic. Existing cards and bank questions reference the appropriate lesson activity. These are application activities in addition to the existing 56 cards and 30 bank questions.

The optional version-1 state field `learning` maps activity-and-stage IDs to `{response, outcome, at, attempts}`. Outcomes are `correct`, `assisted-correct`, `incorrect`, `unassessed`, `self-correct`, `partial`, `needs-work` or `revealed`. Drafts, optional calculation reasoning and rubric checks use namespaced strings in `notes`. Old version-1 backups without this field remain valid. Attempt counts are cumulative; the displayed outcome is the latest outcome. Reveals are assisted study and never scored as independent correctness. Reopening a page alone does not create an attempt.

## Guided paths and selectors (2.1)

`guidedPaths[]` uses objective IDs, with ordered steps `{id, unit, topic, kind, label, visual}`. `kind` is `teach` or `check`. The same source-backed activity may support multiple objectives; the current objective context is displayed explicitly. Each objective ends with two rubric-based transfer checks. The build validates path links and unique objective/step IDs.

Optional `state.guided` stores each objective's current index and reviewed step IDs. Old backups without it remain valid. The current example and its question are visible together; only feedback is gated by submission. Navigation options, question choices and overall ratings use dropdowns. Independent rubric criteria stay checkboxes.
